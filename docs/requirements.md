# 要件定義(初版)

## プロジェクト概要

飼育している生態(魚・爬虫類・昆虫等)と、それらを収容する水槽・ケージの情報を一元管理するシステム。
給餌日のカレンダー管理、水槽/ケージのサイズ・水量から清掃日を自動スケジューリングする機能、AIによる生態の健康管理機能を持つWebアプリケーションとして開発する。

## 想定ユーザー

個人の飼育者(複数の水槽・ケージ、複数種の生態を管理する想定)。

## 主要機能(案)

### 1. 水槽・ケージ管理
- 水槽/ケージごとの登録(名称、サイズ(幅・奥行・高さ)、水量、設置場所、写真など)
- レイアウト情報(底床、フィルター、ヒーター、照明などの機材構成)の登録・編集

### 2. 生態(生き物)管理
- 生態ごとの登録(種名、個体名、導入日、所属する水槽/ケージ、特記事項)
- 生態情報の履歴(成長記録、体調メモなど)

### 3. カレンダー機能
- 給餌日・給餌記録の確認、種ごとの給餌頻度に応じたリマインド
- 清掃日の表示、実施記録
- 外部カレンダー(Google Calendarなど)との同期(要検討・後続フローで詳細化)

### 4. 自動スケジューリング
- 水槽/ケージのサイズ・水量・生体数などから清掃周期を自動算出し、カレンダーに反映
- ロジックの詳細(algorithm)はフロー10で設計

### 5. AI健康管理
- 生態・水槽内データ(水質、給餌記録、体調メモ等)をもとにした健康状態の分析・アラート
- 詳細はフロー11で設計

## 技術スタック(初版・変更可)

- フロントエンド: Next.js (App Router) + TypeScript + Tailwind CSS
- PWA対応(オフラインでも一部閲覧可能を想定)
- バージョン管理: Git / GitHub

## データベース方針(検討)

要件(複数水槽×複数生態のリレーショナルなデータ、カレンダー連携、将来のAI分析)を踏まえた提案:

| 方式 | メリット | デメリット |
|---|---|---|
| Supabase (PostgreSQL) | リレーショナルでデータ構造と相性が良い。認証・ストレージ・Realtimeが標準搭載。無料枠あり。Next.jsとの連携事例が豊富 | 学習コストはFirebaseと同程度 |
| Firebase (Firestore) | セットアップが速い。Google Calendar連携との親和性 | NoSQLのため水槽/生態/記録の関連データ設計がやや煩雑 |
| ローカルDB (SQLite等) | 完全オフライン、無料 | 複数端末同期不可、将来のAI機能拡張に不向き |

現時点の推奨: **Supabase (PostgreSQL)**。理由は、水槽・生態・給餌記録・清掃記録のようなリレーショナルなデータ構造に適しており、認証機能も標準で使えるため。フロー8で最終決定・実装する。

## 決定事項(2026-08-21 ヒアリング)

- 外部カレンダー連携: 不要。アプリ内カレンダーのみで実装する(将来的な拡張候補としては残すが、現行スコープには含めない)
- 対象生態の種類: 魚・爬虫類・昆虫など幅広く対応する。種ごとに管理項目(水温・湿度・給餌頻度など)が異なる前提で設計する
- マルチユーザー対応: 不要。個人利用のみを前提とし、認証はシンプルな構成でよい
